Factory Inventory Management System

System Architecture

A two-tier demo application: a Vue 3 single-page app talks over HTTP/JSON to a stateless FastAPI service that filters in-memory data loaded from JSON files at startup. There is no database, no authentication, and no build-time coupling between the tiers.

Data flow

What happens when a user changes a filter on the Dashboard. Every filtered view follows the same shape; only the endpoint and the subset of filters differ.

  1. User picks a filter client/src/components/FilterBar.vue

    Four <select> elements are bound with v-model to refs exposed by useFilters(): period (month or quarter), warehouse, category, order status. All four selects are always shown; each view simply ignores the filters it does not support.

  2. Shared state updates client/src/composables/useFilters.js

    The refs live at module scope, so every caller of useFilters() sees the same instance — a lightweight store without Pinia/Vuex. getCurrentFilters() maps them to { warehouse, category, status, month }.

  3. View reacts client/src/views/Dashboard.vue

    Each view registers watch([selectedPeriod, selectedLocation, ...], loadData) plus onMounted(loadData). Views only watch the filters they support (Inventory ignores period and status).

  4. HTTP request client/src/api.js

    Builds a query string, dropping any value equal to 'all', and issues axios.get('http://localhost:8001/api/dashboard/summary?warehouse=Tokyo&month=Q2-2025'). Dashboard fires four calls in parallel: summary, inventory, orders, backlog.

  5. Server-side filtering server/main.py

    apply_filters() narrows by warehouse (exact), category and status (case-insensitive). filter_by_month() matches YYYY-MM as a substring of order_date, expanding Qn-2025 via QUARTER_MAP. Aggregates (inventory value, low-stock count, pending orders) are computed on the filtered lists.

  6. Response and render Pydantic → axios → Vue

    List endpoints declare response_model=List[Model] so FastAPI validates and serializes; summary/spending/report endpoints return plain dicts. The view stores raw payloads in refs (allOrders, inventoryItems) and derives charts and tables through computed properties.

Pydantic models

  • InventoryItem, Order, DemandForecast, BacklogItem — used as response_model.
  • RestockCandidate, CreateRestockOrderRequest (with Field constraints), RestockOrder/RestockOrderLine — restocking flow.
  • PurchaseOrder, CreatePurchaseOrderRequest — defined but not referenced by any route yet.

Shared helpers

  • apply_filters(items, warehouse, category, status) — sequential list comprehensions; skips any value equal to 'all'.
  • filter_by_month(items, month) — substring match on order_date; quarters expand through QUARTER_MAP (2025 only).
  • CORSMiddleware with wildcard origins so the :3000 origin can call :8001 directly.

Observations

Things worth knowing before extending the system. These are descriptive, not a to-do list.

Gap

Client references endpoints the server does not implement. api.js defines getTasks/createTask/deleteTask/toggleTask (/api/tasks) and createPurchaseOrder/getPurchaseOrderByBacklogItem (/api/purchase-orders). main.py has no such routes, so App.vue's task load fails quietly and purchase-order creation from the backlog modal will 404. The PurchaseOrder models and empty purchase_orders.json suggest this is planned work.

Coupling

API origin is hard-coded in two places. API_BASE_URL in api.js and literal URLs in Reports.vue. There is no Vite proxy or env-based configuration, so running the API on another host/port requires source edits, and Reports.vue bypasses the shared client entirely.

Design

State management is intentionally minimal. Module-scoped refs in useFilters act as a global store; each view re-fetches on filter change rather than caching. Simple and predictable for a demo; would need debouncing or a query cache at scale.

Design

Filtering is string-based. Month/quarter matching uses substring checks against ISO timestamps and a 2025-only QUARTER_MAP; /api/reports/quarterly re-derives quarters with chained substring tests. Fine for the fixed dataset, brittle if dates move beyond 2025.

Scope

Demo posture. Wildcard CORS with credentials, no auth (useAuth is a mock user), no persistence, synchronous handlers over small in-memory lists. Backlog.vue exists but is not routed; backlog data surfaces through the Dashboard instead.

Size

Two views carry most of the UI weight. Dashboard.vue (1271 lines) and Spending.vue (852 lines) contain inline SVG charting and many computed properties; they are the first candidates for extraction into chart components.
